# Decisions

**Data model.** The simulator seeds 120 environment records. Each contains a learner, lifecycle state, current step, expected step duration, and hourly rate. A deterministic per-environment stream advances the seed from the session start time to the request clock. An append-only log stores reprovision actions. Spend comes from the hourly rate times accumulated billable runtime and stops accruing when an environment deprovisions. A restart can replay the cohort from the session anchor and stored actions. Separate append records allow concurrent instances to write actions for different environments. Warm instances refresh their storage view on a configurable interval.

**Server-side queries.** The environments route loads and replays one cohort per request, then derives filtered rows, the full floor map, and aggregates from that cohort and clock. Polling exposes simulated transitions and brings operator actions back into the dashboard. Each row includes the computed progress, time on step, and estimated spend. The UI’s search, status buttons, advanced filters, and natural-language input all use the same server filter pipeline. Keeping those calculations together gives the two views the same threshold and sort semantics.

**Isolated evaluation.** The shared session remains the default. The instructor can explicitly start an isolated demo with a fresh seed and its own persisted action log. The tab remembers the demo identifier across reloads. Starting a fresh demo selects a new identifier, so the old demo and shared session retain their own actions. The 24-hour expiry bounds the evaluation session. An unavailable or expired identifier receives an API error, and the instructor chooses how to recover.

**AI failure behavior.** The offline compiler handles canonical filters and rejects invalid or unconsumed constraints before any model fallback. The optional model returns a candidate filter. The route rejects malformed objects and checks recognizable constraints against the original request. This check has limited coverage for free-form language. The instructor sees and confirms the candidate before it applies. Editing or clearing the request cancels pending results. Timeouts, invalid output, or a missing provider leave the manual controls usable.

**Next steps.** An authenticated deployment could add instructor permissions and an action audit trail. A production integration would replace the seed and simulated billing with CloudLabs environment and billing data. Workshop observations could inform a more useful stuck threshold, especially for unusually long steps.
